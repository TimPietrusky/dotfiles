# What is NOT in this repo (and how to get it back)

This repo can rebuild the machine's *configuration*. It deliberately does not
contain credentials, identity, or local state. This page is the inventory of
everything that exists on the source machine but is missing here — so an agent
provisioning a new Mac knows the gap is intentional, knows what to ask a human
for, and doesn't silently produce a half-working setup.

**Rule for agents: never create, guess, or fabricate any of the values below.
Stop and hand off to the operator.**

---

## 1. Secrets — never commit these

| Path | What it holds | How to restore |
|------|---------------|----------------|
| `~/.zshenv` | `RUNPOD_API_KEY`, `FAL_API_KEY`, `REPLICATE_API_TOKEN`, `BW_SESSION` — **plaintext** | `install.sh` seeds it from `zsh/.zshenv.example`; operator pastes real keys. See the warning below. |
| `~/.ssh/id_ed25519` (+ `.pub`) | Primary SSH key — GitHub auth is over SSH | Copy from the old Mac over a trusted channel, or generate a new key and add it to GitHub. `~/.ssh/known_hosts` rebuilds itself. |
| `~/.config/gh/hosts.yml` | GitHub OAuth token for `gh` (user `TimPietrusky`) | `gh auth login` — do not copy the file. |
| `~/.codex/auth.json` | OpenAI Codex session | Run `codex` and log in. |
| `~/.claude.json` | Claude Code OAuth account, machine ID, per-project history (84 KB, 23 projects) | Run `claude` and log in. Project history is not worth migrating. |
| `~/.config/agent-slack/credentials.json` | Slack tokens | Re-auth via `agent-slack`. |
| `~/.t3/userdata/clerk-tokens.json` | T3 Code auth session | Launch T3 Code, sign in. |
| `~/.t3/userdata/secrets/*.bin` | `asset-access-signing-key`, `cloud-link-ed25519-key-pair`, `server-signing-key` | Regenerated by T3 Code on first run. |
| `~/.infisical/infisical-config.json` | Infisical login + `secrets-backup/` | `infisical login`. Needed for the Daso console deploy path. |
| `~/.openclaw/discord-bot-token.txt` | Discord bot token | Re-issue from the Discord developer portal. |
| `~/.runpod/config.toml` + `~/.runpod/ssh/` | Runpod API key + pod SSH keys | `runpodctl config --apiKey ...` |
| `~/.dolt/config_global.json` | Dolt user identity / creds | `dolt config --global --add user.email ...` |
| `~/.docker/config.json` | Points at the macOS keychain cred store | Recreated by Docker Desktop on login. |
| `~/.portless/*.pem`, `ca-key.pem` | Local TLS CA + server keys for `*.localhost` | **Do not migrate a CA private key.** Reinstall `portless` and let it mint a fresh CA. |
| `~/Documents/timpietrusky/*.kdbx` | KeePassXC vault — the actual passwords (stale copies also in `~/Downloads`) | Move over the vault yourself, out of band. Never near a git repo. The app's *settings* (`keepassxc.ini`) **are** tracked, see `keepassxc/`. |
| macOS Keychain | Wi-Fi, app tokens, certificates | Not migratable by script — use Migration Assistant or re-auth each app. |

> ### ⚠️ `~/.zshenv` is currently plaintext secrets in `$HOME`
>
> On the source machine `~/.zshenv` holds four live credentials in the clear,
> exported into every shell (so every process, including every agent, can read
> them). Two things worth doing while you're setting up the new Mac:
>
> 1. **Rotate them.** `RUNPOD_API_KEY`, `FAL_API_KEY`, `REPLICATE_API_TOKEN` and
>    the Bitwarden `BW_SESSION` were all read out of the file during this
>    inventory, so they've been through a session transcript. `BW_SESSION` in
>    particular is a decrypted-vault handle and should be re-issued (`bw unlock`).
> 2. **Consider sourcing them from Infisical or `bw get` instead** of hardcoding,
>    since both are already installed. That removes the "one `cat` away" problem
>    and means the new machine never has a plaintext key file at all.
>
> Either way: `.zshenv` stays in `.gitignore`.

## 2. Local state — exists, but not worth migrating

Regenerated automatically; listed so nobody hunts for them.

- `~/.zsh_history`, `~/.zsh_sessions/`, `~/.zcompdump*` — shell history/completion cache.
  (Copy `.zsh_history` by hand if you want your history; it's not config.)
- `~/.claude/` — `projects/`, `sessions/`, `history.jsonl`, `shell-snapshots/`,
  `file-history/`, `telemetry/`, `backups/`, `cache/`. Only the four files under
  `claude/` in this repo matter.
- `~/.claude/memory/` — Claude auto-memory (`MEMORY.md` + per-fact files).
  Personal notes, not config. Copy manually if wanted.
- `~/.codex/` — `sessions/`, `memories*.sqlite`, `state_*.sqlite`, `logs_*.sqlite`,
  `history.jsonl`, `models_cache.json`.
- `~/.t3/userdata/state.sqlite*`, `~/.t3/caches/`, `~/.t3/worktrees/`,
  `~/.t3/userdata/desktop-settings.json` (window geometry).
- `~/Library/Application Support/t3code/` and `.../Cursor/{History,globalStorage,workspaceStorage}`
  — Electron profiles, cookies, caches.
- `~/Library/Preferences/*.plist` for **eqMac** (`com.bitgapp.eqmac`), **Wispr Flow**
  (`com.electron.wispr-flow`), **Granola** (`com.granola.app`) and **Ghostty**
  (`com.mitchellh.ghostty`). Binary plists mixing real preferences with account
  state and window geometry — not portable. Ghostty's real config is the tracked
  `config/ghostty/config`; the other three are per-app settings you re-set after
  signing in (eqMac EQ presets in particular have to be rebuilt by hand).
- `~/.agent-browser/{browsers,sessions}`, `~/.agent-slack/tmp`,
  `~/.openclaw/{browser-profiles,devices,discord-browser,*.png}`.
- `~/.a2go/{venv,cache,models,images,audio,logs,pids}` — multi-GB model cache; re-download.
- `~/.docker/{contexts,buildx,models,sandboxes}`, `~/.gradle`, `~/.android`,
  `~/.expo`, `~/.hermes`, `~/.npm`, `~/.cache`, `~/.terraform.d/checkpoint_*`.
- `~/.config/runpod/update_check.json`, `~/.config/uv/uv-receipt.json`,
  `~/.config/cagent/.cagent_first_run`.
- `~/.beads/`, `~/.daso/` inside project repos — per-project task state, lives with
  each repo, not in dotfiles.

## 6. Known drift on the source machine — fix during migration

- `~/.tmux.conf`, `~/.config/ghostty/config` and `~/.config/karabiner/karabiner.json`
  are symlinked to **`~/dev/runpod/lazy-agent/dotfiles/`**, not to this repo. The
  contents are identical, but the new Mac should link to this repo instead —
  `install.sh` does that correctly.
- `~/.zprofile` had the `brew shellenv` line three times (harmless, deduped here).
- `~/.oh-my-zsh/custom/` carries `zsh-autosuggestions`, `zsh-syntax-highlighting`
  and `powerlevel10k` as git clones — `AGENTS.md` Step 4 re-clones them.
